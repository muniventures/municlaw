# Pluggable AI Coding Harness Adapters (OpenCode & Claude Code)

Status: In progress
Owner: MuniClaw Team

## Goal

Provide a pluggable harness provider architecture in MuniClaw supporting multiple AI coding agent runtimes—specifically OpenCode (pinned v1.18.32 daemon) and Claude Code (Anthropic CLI headless runner)—while maintaining uniform sandbox isolation, event normalization, approval controls, and diff inspection.

## Background & Architecture

The MVP implemented a dedicated VPS supervisor bound specifically to OpenCode v1.18.32 running on loopback. However, development teams often use different agent harnesses depending on project complexity, model affinity, or corporate licensing.

### Key Invariants

1. **Uniform Sandbox & Fencing**: Regardless of which harness executes a task, the task must run inside the strict unprivileged sandbox (`/tmp/municlaw/tasks/{taskId}/worktree` and isolated home), denying access to host Docker sockets and cloud metadata.
2. **Canonical Event Normalization**: All raw harness events (OpenCode SSE events, Claude Code stream messages) map to MuniClaw's canonical `TaskEventType` enum (`StepStarted`, `TextDelta`, `ReasoningDelta`, `ToolCalled`, `ToolSuccess`, `ToolFailed`, `DiffUpdated`, `ApprovalRequested`, `ApprovalResolved`, `Error`).
3. **Pluggable Resolution**: The worker supervisor resolves the requested harness adapter dynamically from an extensible harness registry (`IHarnessRegistry`), selecting the right runtime based on `TaskRun.HarnessType`.
4. **Sub-100ms Abort Bounds**: All harness adapters must support immediate cooperative or process cancellation within <100ms upon lease loss or user cancellation.

## Supported Harnesses

1. **OpenCode (v1.18.32)**:
   - Headless daemon running on loopback with `OPENCODE_SERVER_PASSWORD`.
   - Native HTTP/SSE session and prompt protocol.
2. **Claude Code**:
   - Headless CLI execution mode (`claude --non-interactive` / process harness).
   - Structured JSON/stream parsing into canonical task events.
   - Diff extraction via git working directory inspect.
