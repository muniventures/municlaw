## Phase plan

1. T00 proves the external harness, provider proxy, session recovery, and sandbox design on a disposable environment. Freeze DTO/event and authorization contracts before dependent implementation.
2. T10 and T20 build against those contracts. Their parallelization is an implementation option, not authorization to spawn agents.
3. T30 integrates the separate console with real backend/worker behavior.
4. T90 exercises all providers and both Git hosts, isolation, restart/revocation paths, and mobile layouts before private release.

## Execution rules

- Follow folder instructions and existing .NET/React conventions; preserve unrelated worktree changes.
- Update the overview, sub-spec status, this plan, backlog, registry, and affected architecture docs when implementation changes their contracts.
- No custom coding engine, multiple harnesses, messaging integrations, or production-deployment workflow in this scope.
- Do not claim unsupported harness functionality; qualification failures require revising the adapter or explicitly narrowing the contract.
- Never push or deploy without explicit authorization.

## Completion gate

All sub-spec acceptance criteria pass with recorded evidence; a user can create a coding task at the separate console, leave, return, inspect actual changes/checks, publish a draft PR/MR, and continue the task. No cross-organization access or exposed administrative credentials. Public billing and preview deployment are not completion criteria.
