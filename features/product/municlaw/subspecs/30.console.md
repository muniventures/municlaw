# T30: Separate responsive console

Status: Complete.
Depends on: T10, T20.
Can run in parallel with: None.

## Work

- Create the independent frontend/deployment for proposed `ai.muni.dev`, reusing repository-supported React/shadcn and identity conventions.
- Implement Tasks, Projects, Connections, Workspace, and Settings with private onboarding and organization selection.
- Support repository/base-branch/model selection, personal key entry, queued/running tasks, SSE activity with cursor replay, configurable capability policy, approvals, cancellation, and follow-up turns.
- Show changed files, actual check commands/exit results, estimated usage with unknown states, retention expiry/reconstruction limits, and publication approval bound to the reviewed repository/base/target/commit tuple.
- Provide responsive mobile task creation, approvals, result review, and cancellation; keyboard and screen-reader access must work.
- Keep provider keys write-only; no direct browser connection to worker/OpenCode endpoints.

## Acceptance

- Console has separate origin, app shell, and deployment from `cloud.muni.dev`; shared sign-in does not bypass MuniClaw allowlisting.
- Closing/reopening the browser restores task state/history; replay does not duplicate events.
- A stale approval or edited-after-review publication is rejected and requires review of current state.
- Desktop and narrow mobile rendered checks cover onboarding, running/offline/failed tasks, approvals, diffs, and draft delivery.
- Native mobile, messaging, and preview UI are not presented as available features.

## Implementation Evidence

1. **Scaffold & Architecture (`modules/ui/dashboard/`)**:
   - Built on React 19, TypeScript 5.7, React Router 7, Vite 6, Tailwind CSS v4, Lucide React, and shadcn component patterns.
   - Configured route -> module -> component pattern conforming to `docs/architecture/frontend.md`.
   - Public runtime configuration (`app/core/config/runtime.ts`) ensuring no secrets or private worker endpoints are exposed to the client.

2. **Responsive App Shell & Routing**:
   - `AppShell`, `Sidebar`, `Header` in `app/core/layout/` support full keyboard navigation (Escape to dismiss, focus trap, skip to main content), accessible ARIA roles, and responsive mobile nav drawer.
   - Navigation routes: Tasks (`/tasks`), Task Detail (`/tasks/:taskId`), Projects (`/projects`), Connections (`/connections`), Workspace (`/workspace`), Settings (`/settings`), and Onboarding (`/onboarding`).

3. **Feature Modules (`app/modules/`)**:
   - `TasksModule` & `TaskDetailModule`:
     - Task list with search, status filtering, and task creation trigger.
     - Task creation modal with repo project, base branch, model selection (`claude-3-7-sonnet`, `claude-3-5-sonnet`, `gpt-4o`, `gpt-4.5`), BYOK credential selection, and prompt.
     - Live activity stream (`ActivityLog`) consuming SSE events with auto-scroll and folding of agent reasoning deltas.
     - Changed files view (`DiffView`) rendering unified git diffs, additions/deletions stats, and review commit SHAs.
     - Test verification checks (`CheckResults`) presenting actual check commands, exit codes, and raw stdout/stderr logs.
     - Approval request banner (`ApprovalBanner`) with AllowOnce/Deny actions and stale approval rejection handling.
     - Draft publication modal (`DeliveryModal`) bound strictly to the `(repo, base, target, commit)` review tuple, protecting against modified-after-review drift.
     - Follow-up input (`FollowUpInput`) supporting subsequent turns on the same task branch.
     - Resource usage card (`UsageCard`) accurately reflecting token metrics, estimated cost USD with price provenance, unknown states, and retention limits.
   - `ConnectionsModule`:
     - GitHub and GitLab connection management.
     - Personal BYOK key entry (`CredentialKeyEntry`) with strictly write-only input (`type="password"`, never returned in API responses or retained in frontend state).
   - `WorkspaceModule`:
     - Explicit onboarding action to request dedicated organization VPS on Minicloud.
     - Displays VPS provisioning status (`Pending`, `Ready`, `Failed`, `Terminated`), IP address, one-time supervisor registration token, and status refresh/termination controls.
   - `SettingsModule`:
     - Organization profile settings with private allowlisting indicator.
     - Capability approval policies matrix (`CapabilityPolicyTable`) with configurable `Allow`, `Ask`, `Deny` controls and immutable `PlatformDenied` lock.
   - `OnboardingModule`:
     - Dedicated private preview verification route enforcing allowlist requirements before console use.

4. **API Clients & SSE Cursor Replay**:
   - Shared HTTP client (`app/api/client.ts`) calling same-origin `/api/v1/...` with structured error handling.
   - Centralized SSE manager (`app/api/sse.ts`) with monotonic cursor replay (`Last-Event-ID`), sequence tracking, session-persisted cursor, event deduplication, and exponential backoff reconnection.

5. **Verification**:
   - `npm run typecheck`: 0 errors.
   - `npm run build`: Static client bundle (`build/client/index.html` + asset chunks) successfully compiled in 1.09s.
   - `npm test`: 4/4 Vitest tests passed covering HTTP client error handling, SSE stream deduplication, and policy security invariants.
