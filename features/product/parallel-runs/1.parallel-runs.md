# Feature: Parallel Task Execution and Concurrency Scheduling

Scope: Organization concurrency quotas, automated FIFO task queueing, promotion on terminal transitions, and console queue/slot visualization.

## Agent instructions

- Use stable task IDs (`T10`, `T20`, `T90`).
- Keep live task status in `0.execution-plan.md`.
- After finishing tasks, update subspecs, `0.execution-plan.md`, `features/FEATURE_BACKLOG.md`, and `features/FEATURES_REGISTRY.md`.
- Concurrency limit checks must be atomic and thread-safe to avoid race conditions and over-admission.
- A task waiting for approval (`AwaitingInput`) retains its execution slot to guarantee state preservation.

## Goal

Enable organizations to execute multiple coding tasks in parallel up to an administrator-configured concurrency quota (`MaxConcurrentRuns`). When all execution slots are occupied, additional submitted tasks enter a fair FIFO queue and are automatically promoted to execution as active tasks complete, fail, or cancel.

## Current patterns learned

- MVP enforced a strict single-active-task rule per organization in `TaskLifecycleService`.
- Tasks have statuses: `Queued`, `Preparing`, `Running`, `AwaitingInput`, `Completed`, `Failed`, `Cancelled`.
- `TaskRunStateTransitions` governs lifecycle transitions.
- Worker dispatch leases have 30s fencing heartbeats.

## Scope and non-goals

### In scope

- Organization concurrency quota (`Organization.MaxConcurrentRuns`, default 2, configurable by admins).
- Multi-task execution: Multiple runs in `Preparing`, `Running`, or `AwaitingInput` can execute simultaneously within the quota.
- Automated FIFO task queueing:
  - Tasks created when active runs < quota start immediately in `Preparing`.
  - Tasks created when active runs >= quota remain in `Queued` with a tracked queue position (`QueuePosition`).
  - Terminal state transition (`Completed`, `Failed`, `Cancelled`) of any active run automatically triggers `TaskQueueService.PromoteNextQueuedTaskAsync` to advance the oldest queued task into `Preparing`.
- Console UI updates:
  - Slot usage counter (`Active Tasks: X / Y slots in use`).
  - Queue position badges on queued tasks (`Queued #1`, `Queued #2`).
  - Task Detail view banner informing users of their queue position and estimated time.
  - Organization settings tab allowing administrators to configure the concurrency quota.

### Out of scope

- Multi-cluster distributed scheduler algorithms (single-cluster queueing is sufficient).
- Dynamic worker autoscaling in cloud hypervisors (managed by host VPS capacity).

## Requirements

### Runtime and scheduling requirements

- Admission control: Atomically count active non-terminal runs for the organization before advancing a task to `Preparing`.
- Queue order: Strict FIFO based on `CreatedAt` timestamp.
- Immediate promotion: On run completion, failure, or cancellation, the queue scheduler immediately signals the next eligible task to claim worker resources.
- Worker capacity: Workers can claim work up to their local concurrency limit.

### Security and tenancy

- Concurrency quotas and queues are strictly organization-isolated; one organization's queue never blocks or delays another organization's tasks.
- Only organization administrators can increase or modify concurrency quotas.

### Verification

- Automated tests verifying parallel execution up to quota.
- Automated tests verifying FIFO queue ordering when quota is saturated.
- Automated tests verifying automatic promotion of queued tasks upon active run completion.
- Automated tests verifying automatic promotion upon active run cancellation.
