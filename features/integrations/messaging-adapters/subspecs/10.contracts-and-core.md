# Subspec: Notification Contracts, Formatters, and Core Dispatch

Task: `T10`
Status: Complete

## Scope

- Domain models: `NotificationChannel`, `NotificationEventType`, `TaskLifecycleNotification`.
- Adapters & Formatters:
  - Slack Block Kit formatter with header, markdown fields, summary section, and "View in Console" action button.
  - Discord Embed formatter with severity color mapping (`ApprovalRequested`: 0xF59E0B, `TaskCompleted`: 0x10B981, `TaskFailed`: 0xEF4444, `DeliveryPublished`: 0x3B82F6), fields, timestamp, and console URL.
  - Generic Webhook formatter with full event payload serialization and HMAC-SHA256 signature generator (`X-MuniClaw-Signature` and `X-MuniClaw-Timestamp`).
- Services: `NotificationService` implementing channel management (create, update, delete, list), non-blocking HTTP dispatch, and live test ping.
- Persistence: Storing channels in `IMuniClawStore` (`ConcurrentDictionary<Guid, NotificationChannel>`) and snapshotting in `MuniClawFileStore`.
- API: `NotificationsController` with channel CRUD, masked webhook URL projection, and test dispatch endpoints.

## Implementation Details

### Domain Models (`modules/core/Models/NotificationModels.cs`)
- `NotificationChannelType`: `Slack`, `Discord`, `GenericWebhook`.
- `NotificationEventType`: `ApprovalRequested`, `TaskCompleted`, `TaskFailed`, `DeliveryPublished`.
- `NotificationChannel`: Represents a configured integration channel for an organization, storing channel type, webhook URL, optional HMAC signing secret, subscribed event types, enabled status, and last dispatch status/timestamp.
- `TaskLifecycleNotification`: Carries event context including `EventType`, `TaskId`, `RunId`, `OrganizationId`, `TaskTitle`, `RepositoryName`, `Branch`, `Timestamp`, `Summary`, and `ConsoleUrl`.

### Contracts & DTOs (`modules/core/Contracts/Notifications/NotificationContracts.cs`)
- `CreateNotificationChannelRequest`: Name, ChannelType, WebhookUrl, SubscribedEvents, SigningSecret.
- `UpdateNotificationChannelRequest`: Name, WebhookUrl, SubscribedEvents, IsEnabled, SigningSecret.
- `NotificationChannelDto`: Projected channel representation with `MaskedWebhookUrl` redacting tokens and secrets from path segments and query strings.

### Payload Formatter (`modules/core/Services/NotificationService.cs`)
- `NotificationPayloadFormatter.FormatSlack`: Generates Slack Block Kit JSON with `header`, `section` fields, summary, and action button.
- `NotificationPayloadFormatter.FormatDiscord`: Generates Discord Embeds JSON with mapped severity colors and inline fields.
- `NotificationPayloadFormatter.FormatGeneric`: Generates camelCase JSON payload of the event.
- `NotificationPayloadFormatter.ComputeHmacSignature`: Computes hex HMAC-SHA256 of `{timestamp}.{payload}` using the configured signing secret.

### Core Dispatch Service (`modules/core/Services/NotificationService.cs`)
- `CreateChannelAsync`: Validates input, auto-generates HMAC secret for generic webhooks if omitted, and saves channel.
- `UpdateChannelAsync`: Updates channel properties and persists snapshot.
- `DeleteChannelAsync`: Removes channel from store.
- `ListChannelsAsync` / `GetChannelAsync`: Queries channels scoped by organization.
- `DispatchNotificationAsync`: Filters enabled channels matching event type, asynchronously posts formatted payloads with 10-second timeout, records `LastDispatchedAt` and `LastDispatchStatus`, and safely catches dispatch errors without throwing.
- `SendTestPingAsync`: Generates a synthetic test notification and dispatches to a specific channel for immediate validation.

### Store Integration (`modules/core/Data/MuniClawStore.cs`, `modules/core/Data/MuniClawFileStore.cs`)
- Added `NotificationChannels` concurrent dictionary to `IMuniClawStore`, `InMemoryMuniClawStore`, and `MuniClawFileStore`.
- Integrated into file snapshot serialization, loading, and clear routines.

### Webhook Management API (`modules/api/Controllers/NotificationsController.cs`)
- `GET /api/v1/notifications/channels`: List notification channels for organization.
- `GET /api/v1/notifications/channels/{channelId}`: Get single notification channel.
- `POST /api/v1/notifications/channels`: Create a new notification channel.
- `PUT /api/v1/notifications/channels/{channelId}`: Update existing channel.
- `DELETE /api/v1/notifications/channels/{channelId}`: Delete channel.
- `POST /api/v1/notifications/channels/{channelId}/test`: Send test ping to verify webhook connectivity.
