# Subspec: Standalone Persistence and Secrets

Task: `T10`
Status: Complete

## Scope

- `MuniClawFileStore`: Durable, atomic JSON-backed store implementing `IMuniClawStore`.
- `LocalEncryptedSecretStore`: Standalone AES-256-GCM secret store with tamper detection and master-key derivation.
- `OpenBaoHttpClient`: Concrete HTTP client targeting OpenBao / Vault KV-v2 endpoints (`/v1/secret/data/...`).
- `sql/schema.sql`: Full DDL schema for PostgreSQL multi-tenant self-hosting.

## Implementation Summary

1. **`MuniClawFileStore` (`modules/core/Data/MuniClawFileStore.cs`)**:
   - Implements `IMuniClawStore` backed by thread-safe `ConcurrentDictionary` collections for all 13 MuniClaw domain entities (Organizations, Users, Memberships, Workspaces, RepositoryConnections, Projects, ProviderCredentials, Tasks, TaskRuns, TaskEvents, ApprovalRequests, Deliveries, UsageRecords).
   - Guarantees crash-resilient durability using atomic temporary-file writes (`snapshot.{guid}.tmp`) followed by atomic filesystem swap (`File.Move(..., overwrite: true)`).
   - Provides public `SaveSnapshot()` and `LoadSnapshot()` methods with JSON reference cycle handling and automatic fallback between `snapshot.json` and `municlaw-store.json`.
   - Thread-safe serialization and deserialization guarded by dedicated synchronization locks.
   - Fully implements organization-scoped credential policy and spend accounting methods (`StoreOrganizationCredential`, `GetOrganizationCredentials`, `UpdateCredentialPolicy`, `IncrementCredentialSpend`, `Clear`).

2. **`LocalEncryptedSecretStore` (`modules/core/Integrations/LocalEncryptedSecretStore.cs`)**:
   - Implements `IOpenBaoClient` for single-node standalone deployments without external HashiCorp Vault / OpenBao dependencies.
   - Uses authenticated encryption with `System.Security.Cryptography.AesGcm` (12-byte cryptographic random nonce, 16-byte authentication tag).
   - Payload format: `[Nonce (12B)][Tag (16B)][Ciphertext (NB)]`.
   - Automatic master key derivation supporting raw 32-byte arrays, 44-character Base64 keys, 64-character Hex keys, or arbitrary string passphrases via SHA-256.
   - Strict Unix file permissions (`0600` - UserRead/UserWrite) enforced at creation and rename on Linux/macOS.
   - Throws `CryptographicException` upon tag mismatch, ciphertext tampering, or invalid master key.
   - Provides zeroing memory/disk overwrite before file unlinking on `DeleteSecretAsync`.

3. **`OpenBaoHttpClient` (`modules/core/Integrations/OpenBaoHttpClient.cs`)**:
   - Concrete HTTP client implementing `IOpenBaoClient` targeting OpenBao and HashiCorp Vault KV-v2 secret engines.
   - Store: `POST /v1/secret/data/{path}` sending `{"data": secretData}` with `X-Vault-Token` header.
   - Get: `GET /v1/secret/data/{path}` extracting secret key-value pairs from `data.data`, gracefully returning `null` on HTTP 404.
   - Delete: `DELETE /v1/secret/metadata/{path}` for complete secret metadata erasure.
   - Redacts vault tokens in all HTTP error and exception messages (`[REDACTED]`).

4. **PostgreSQL Schema (`sql/schema.sql`)**:
   - Comprehensive production PostgreSQL 14+/16+ DDL script for enterprise multi-node self-hosting deployments.
   - Covers all 13 core domain entities: `organizations`, `users`, `memberships`, `coding_workspaces`, `repository_connections`, `projects`, `provider_credentials`, `tasks`, `task_runs`, `task_events`, `approval_requests`, `deliveries`, `usage_records`.
   - Includes UUID primary keys (`gen_random_uuid()`), foreign key cascades, unique constraints, check constraints on enums and states, and performance indexes for tenant lookups, cursors, and lease timestamps.
