## Goal

Provide a turnkey, self-hosted distribution of MuniClaw that operators can deploy on a single dedicated VPS or in their own infrastructure without a dependency on Minicloud's proprietary management plane or external managed services.

## Current patterns learned

- MVP used an in-memory store (`InMemoryMuniClawStore`) and mock clients (`MockOpenBaoClient`, `MockMinicloudWorkspaceClient`).
- Secret paths follow `municlaw/{orgId}/credentials/{credId}`.
- Worker communicates with the API via loopback or HTTPS with shared registration tokens.

## Scope and non-goals

### In scope

- Standalone durable store (`MuniClawFileStore`) implementing `IMuniClawStore` with atomic file flushing, mutex locks, and snapshotting.
- PostgreSQL production schema script (`sql/schema.sql`) for enterprise multi-node deployments.
- Concrete OpenBao / HashiCorp Vault HTTP client (`OpenBaoHttpClient`) targeting the KV-v2 engine.
- Standalone AES-256-GCM encrypted local secret store (`LocalEncryptedSecretStore`) implementing `IOpenBaoClient` for lightweight single-node self-hosting.
- Production multi-container `docker-compose.self-host.yml` and container build manifests (`Dockerfile.api`, `Dockerfile.worker`, `Dockerfile.dashboard`, `nginx.conf`).
- Host bootstrap script (`scripts/self-host/bootstrap-host.sh`) and systemd service definition (`scripts/self-host/municlaw-worker.service`).
- Comprehensive operations and installation guide (`docs/architecture/self-host-guide.md`).

### Out of scope

- Multi-region geo-replication or Kubernetes Helm charts (reserved for later enterprise roadmap).
- Public SaaS billing or Stripe integration.
- Replacing OpenCode with other coding harnesses.

## Requirements

### Runtime and storage requirements

- The standalone store must survive application restarts without data loss.
- Atomic file writes prevent database corruption during sudden machine crashes.
- The secret store must encrypt credentials at rest with an operator-supplied master key (`MUNICLAW_MASTER_KEY`).
- Secret files or paths must never expose raw tokens.

### Deployment & packaging requirements

- Operators can bring up the full MuniClaw stack with a single command: `docker compose -f deploy/docker-compose.self-host.yml up -d`.
- Workers can run either as a container or as a native systemd service on a dedicated Linux VPS.
- OpenCode v1.18.32 is installed and pinned during host bootstrap.

### Verification

- Automated tests verifying file store durability, restart recovery, concurrent writes, and atomic swaps.
- Automated tests verifying AES-256-GCM secret encryption, tampering detection, and path isolation.
- Compose syntax validation and build verification.
